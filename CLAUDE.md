# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Gold buy/sell zone advisor** — a free PWA that helps the user (Vietnamese, buys physical SJC/ring gold) decide when to buy or sell. It is NOT a price tracker: it scores buy/sell zones across multiple criteria and reports a probability-style confidence %, validated by backtest. No prediction claims — decision support only.

Status: fully built and committed. Original design doc: `docs/superpowers/specs/2026-06-11-gold-zone-advisor-design.md`; preset methodology + all study evidence: `docs/presets.md` (keep its tables in sync with `PRESETS` in `src/lib/types.ts`). User communicates in Vietnamese; UI text is Vietnamese.

Key commands: `npm run collect` (fetch + analyze + backtest → public/data/), `npm test`, `npm run build`, `npx tsx scripts/monitor-presets.ts` (preset health), `npx tsx scripts/check-modes.ts` (print all-mode composites for UI debugging). Studies: `presets-study`, `factor-study`, `factor-study-momentum-offline` (offline 4D ablation), `premium-buy-study` (premium gating for buy), `single-factor-study`, `horizon-study`, `optimize-study`, `backfill-vn` (one-off CafeF history import), `npx tsx scripts/bottom-study.ts` (Bottom Hunter ε/H + weight grid search), `npx tsx scripts/bottom-ml-study.ts` (ML vs rule-based gate), `accumulation-study` (tuyển phanh DCA, cổng 2 giai đoạn + CI + placebo).

## Agreed architecture (Approach A — do not silently change)

All analysis runs at data-collection time, not at page load. The Git repo is the database.

- **GitHub Actions cron (2×/day):** fetches prices → runs scoring engine → runs backtest → commits results as JSON under `data/` → auto-deploys.
- **Static PWA (Vercel or GitHub Pages):** reads precomputed `data/*.json` only. No external API calls from the browser (CORS is why), no server, no paid services anywhere.
- Stack: Next.js + TypeScript, static export.

Cron failure must never blank the app: keep last data, show a "data is N days old" warning.

## Scoring engine (core domain logic)

Each criterion = multiple sub-signals, each scored **−2..+2** (negative = sell-leaning, positive = buy-leaning) with a Vietnamese explanation string. Four criterion groups with default weights (user-adjustable in settings):

1. **XAU/USD technicals (35%)** — RSI(14) daily+weekly, MA50/MA200, 52-week high/low distance, support/resistance from 6-month swings
2. **VN–world premium (25%)** — SJC vs converted world price (percentile vs premium history; high premium = sell signal / don't buy), SJC bid-ask spread width, ring-vs-bar anomaly
3. **Macro (20%)** — DXY vs MA50 + 1-month trend, Fed rate direction, USD/VND pace
4. **Historical stats (20%)** — price percentile vs 1y/3y, monthly seasonality (Tết / Thần Tài effects), 30-day volatility

Composite: weighted sum normalized to −100..+100. Thresholds: ≥+40 BUY zone (≥+70 strong), ≤−40 SELL zone (≤−70 strong), otherwise NEUTRAL.

An independent **Bottom Hunter** layer (2-tier cycle/swing near-bottom probability, driven by RSI oversold + macro reversal, validated out-of-sample, see `docs/bottom.md`) reports a near-bottom % with CI and does NOT touch the buy/sell composite.

An independent **Accumulation brake** layer (DCA sizing: ease off buying — never to zero — when XAU is expensive vs its trailing 2-year range; single price gate, validated 2-period, see `docs/accumulation.md` — the old composite co-gate was dropped by ablation, `scripts/accumulation-ablation.ts`) suggests a buy-size multiplier and does NOT touch the composite or Bottom Hunter. Since 2026-07-03 it has NO UI surface (its Time Machine line showed ×0.25 while the Bear DCA card said ×1.0 for the same day — Time Machine now shows Bear DCA's `bearDcaAt()` instead); the engine + `accumulation.json` + health monitor still run each cron.

An independent **Bear DCA Advisor** layer (`src/lib/bear-dca.ts`, replaces AccumulationCard in the UI) classifies the market into 4 phases from drawdown-from-ATH + ddChange (bull / acute crash / recovery / grind) and suggests a buy-size multiplier per phase; hybrid (user can override the phase). Reaction-based, NOT prediction. Bottom Hunter, composite, presets, MA200, and multi-year trend prediction were all tested and REJECTED for this decision (forward-return signals don't help the 2–3yr cost objective; placebo near-matches). See `docs/bear-dca.md` (keep its evidence tables synced with the `bear-*-study.ts` scripts). Does NOT touch the composite, Bottom Hunter, or Accumulation brake. **Health monitor (`monitorBearDca`, fixed 2026-07-03):** scores ONLY bear cycles (≥6 required, else `insufficient` — bull cycles have q=1 and dilute the score to 0, which used to flag "degraded" spuriously), reports BOTH cost-basis (`recentImprPct`, bear cycles) and final-asset (`recentAssetImprPct`, whole window) vs flat, and `degraded` only below a −0.5pp noise band. **The Time Machine shows this layer's as-of multiplier via `bearDcaAt()`** (golden-tested ≡ `runBearDca`) — it previously surfaced the old Accumulation brake (×0.25) which contradicted this card on the same day. ddChange sign convention: positive = drawdown DEEPENING, unit "điểm %/tháng" (pp of dd, not price %).

An independent **Bear Downside** layer (`src/lib/bear-downside.ts`, "Triển vọng 1/3/6 tháng tới" card) reports, at 1/3/6-month horizons (12-month dropped — only ~20 independent windows + strongest bull bias), BOTH sides as USD price levels: the **worst-dip risk** (`min(future price over H)/today − 1` — median, p10, P(bottom already behind)) AND the **terminal outcome** (`price[t+H]/today − 1` — median end return + P(price higher than today), `endMedian`/`pUp`), all with block-bootstrap CI. Two-sided by design (a prior one-sided worst-dip-only card read as misleadingly bearish). Context/reaction, NOT prediction. Conditioning the distribution on current drawdown-from-ATH bucket was tested and REJECTED (`conditioningWorks=false` in `BEAR_DOWNSIDE_CONFIG`): deeper buckets don't monotonically change the distribution and CIs overlap the unconditional, unstable across train/test (gold rarely falls >30% so deep buckets are sparse/noisy). **Conditioning on composite/zone/MA200/momentum was ALSO tested and REJECTED** (2026-07-03, `scripts/bear-downside-conditioning-study.ts`): none reduces median MAE, MA200/zone×trend make it worse — so "combine with the composite" does NOT help (composite is a value/contrarian signal that sits in neutral through bulls; zone is too imbalanced to validate out-of-sample). The distribution IS **recency-weighted** (`recencyHalflife=504` ≈2yr, `0.5^(age/halflife)`) to correct a statistically-significant regime-drift bias (unconditional median undershoots ~+7% at 126p in bull, overshoots in the 2013 bear; `scripts/bear-downside-calibration-study.ts` — bias reduced both directions/regimes; footgun-in-drawdowns not confirmed). **Honest caveat: the MAE gain is NOT statistically significant (variance-dominated) — recency is a BIAS/regime correction, not a forecast**; 504 (not the cleaner-de-biasing 252) chosen because 252/504 are statistically indistinguishable and 504 tempers extreme post-parabolic readings for a decision-support card. Applied identically to `runBearDownside` + `runBearDownsideHistory` via `computeHorizonStat(..., {ages, termAges, halflife})` so the as-of golden invariant holds. **pUp calibration was backtested** (`scripts/bear-downside-pup-study.ts`, Brier score): pUp is NOT "too optimistic" — gold's 6-month up-rate is genuinely ~80% in the recent (bull) regime, and recency-504 is better-calibrated than unconditional in BOTH train (2013 bear) and test (shrinking pUp toward 50%/unconditional worsens Brier). **Anti-illusion presentation** (2026-07-03, `scripts/…`-backed design in `docs/superpowers/specs/2026-07-03-bear-downside-anti-illusion-design.md`): the card shows the terminal column as a **p25→p75 range** (`endP25`/`endP75` added to `BearHorizonStat`+`BearAsOfBand`) not a point, prices rounded `~$X.Xk`, an always-visible regime caveat, and "Khả năng ↑/↓" (both sides) instead of one-sided "Cơ hội tăng" — to block four misreadings (median-as-forecast, false precision, unseen bull-weighting, one-sided anchoring). This is a display layer; it does NOT change the statistics. **Reliability patch (2026-07-03, post-review):** (a) CIs in the JSON are now computed in the SAME weighting scheme as the point estimates via `weightedBlockBootstrapCi` — the old unweighted CIs were invalid (live pUp 83.5 sat OUTSIDE its own [57, 79.1]); test-locked "estimate ∈ own CI". (b) The "Khả năng" column displays pUp coarsened to tenths (`pUpTenths`, clamp 1..9 → "≈8/10↑") because the recency-weighted ESS is only ~12 independent 6-month windows (SE ±~10pp) — decimal percentages were false precision. (c) Bands require `enoughSamples(n,H)`: n≥30 AND n·STEP/H ≥ 10 independent windows (126p needs n≥420). (d) The card's info banner shows MEASURED walk-forward coverage (`coverageStats`): terminal outcome inside p25–p75 = 53/48/46% (1/3/6T, expect ~50), dip beyond p10 = 8/8/9% (expect ~10). **Un-weighting (or min-ing) the DIP side as a "conservative counterweight" was tested and REJECTED** (`scripts/bear-downside-dipside-study.ts`): weighted-504 exceed% tracks the ~10% target in BOTH eras; unweighted/min collapse to 2.9–7.7% in test = systematically over-deep risk display. See `docs/bear-downside.md` (keep evidence synced with `scripts/bear-downside-study.ts`, `bear-downside-conditioning-study.ts`, `bear-downside-calibration-study.ts`, `bear-downside-pup-study.ts`, `bear-downside-dipside-study.ts`). Does NOT touch the composite, Bottom Hunter, Bear DCA, or Accumulation brake.

**Tested and REJECTED — intra-month DCA timing (NO-GO, do not re-add without re-running `scripts/dca-timing-study.ts`):** picking a "good" entry day *within* the month (relative-position, RSI-oversold, or month-drawdown rules) gives no durable cost-basis edge over buying on day 1 — no rule beat baseline + placebo across train(<2019)/test(≥2019), validated by reproduction. No UI shipped; Bottom Hunter kept. Evidence + method: `docs/dca-copilot.md`; research code: `src/lib/dca-sim.ts`, `src/lib/dca-zone.ts`, `scripts/dca-timing-study.ts`. **Re-opened and re-confirmed (DCA Zone v2, `docs/dca-zone-v2.md`, `scripts/dca-zone-study-v2.ts`, `src/lib/dca-window.ts`):** with the *right* metric (paired rangePos over a rolling **30-day-forward** window, not 15yr cost basis) + full classic TA (Bollinger %B / Stochastic %K / RSI / z-score / relpos / drawdown / pullback) + a volatility gate, still NO-GO — no rule beats "buy now" + placebo (CI straddles 0) in both train/test. Key reason (validated): **buy-now (day 0 of the forward window) already sits ~0.41 of the window range** because gold trends up, so there's almost no headroom to time. Practical takeaway: don't wait to time the dip — buying now / DCA steadily is fine. (Bear downside distribution = shipped, see Bear Downside layer above; between-months skip = not studied.)

**Backtest rule (integrity-critical):** confidence % must come from replaying the engine over ~15 years of XAU/USD history (e.g., "BUY signal at this level: 134 occurrences, 71% higher after 3 months, avg +4.2%"). VN-premium criterion is only backtested once ≥6 months of self-collected data exists; before that the UI must say "chưa đủ dữ liệu kiểm chứng" — never fabricate a number.

**Backtest must mirror the live engine's criterion gating (do not silently change):** the historical timeline (`scripts/backtest.ts`) computes the macro criterion whenever DXY is available — Fed, 10y yield, USD/VND are optional, exactly as `macroCriterion` skips its own missing sub-signals on the live path. Do NOT gate macro on all inputs being present (`if (dxy && fed)`): the presets weight macro at 0.9, so a single missing input there silently strips 90% of every preset's signal from all history and produces zero buy signals in a clear uptrend. Regression-guarded by the "includes the macro criterion when DXY is present but Fed is missing" test.

**Sparse-stats / dense-display split (do not silently unify):** `scripts/backtest.ts` and `src/lib/bottom.ts` each run TWO sampling grids. Statistics — backtest `buckets`, bottom `prob`/`ci`/`n` — sample every `STEP`(=3) sessions to avoid pseudo-replication: adjacent days have overlapping forward-return windows, so scoring every day inflates `n` and shrinks the CI falsely (a 39% near-bottom would read as deceptively confident). Display — `timeline.points`, `signalHistory`, `confirmedBottoms` — sample every session (step 1) so the Time Machine can look up any trading day (T2–T6; XAU has no weekend bar). Do NOT make the stats grid dense to "simplify": the value of a day (bin, return, zone) is a pure function of that day, so the dense set is a superset that adds days without shifting existing stats — that equality is locked by golden tests (backtest `observations`+bucket snapshot, bottom `n`/`prob`). Verified old-vs-new engine byte-identical on the same bars.

## Conventions

- UI language: Vietnamese. Signal explanations are user-facing Vietnamese strings, not codes.
- Everything must run on free tiers (GitHub Actions, Vercel/GitHub Pages, FRED free key). Reject designs requiring paid infra.
- Historical VN gold data is scarce: the daily cron commit IS the accumulation strategy — protect `data/` history, never rewrite it.
